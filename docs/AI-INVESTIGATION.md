# AI 调查任务（Investigation）设计

> 用户需求：给 AI 定一个任务，让它自己去翻录像找答案

---

## 一、为什么这是最有价值的功能

现在的监控是「**你去看**」：

```
发生事情 -> 你收到通知 -> 你打开 App -> 你一段段翻录像 -> 你自己判断
```

真正想要的是「**AI 帮你找**」：

```
你有疑问 -> 告诉 AI -> AI 自己翻 -> 给你结论 + 证据 + 一键定位
```

---

## 二、三种任务类型

### 2.1 查找类 find

```
问：「最近三天有人经过我的车吗？」

AI 做的事：
  1. 解析成计划 {设备: 门口, 时间: 3天, 目标: 车辆附近的人}
  2. 用【本地事件库】筛候选（免费，不扫全部录像）
  3. 每条抽一张高清帧，问 AI：「这张里有车吗？旁边有人吗？」
  4. 收集命中的 -> 证据列表
  5. 汇总成结论

返回：
  结论：最近三天有 3 次人员经过你的车
  证据：
    09-15 14:23  门口  有人靠近车尾   [图] [定位回放]
    09-16 08:41  门口  快递员经过      [图] [定位回放]
```

### 2.2 比对类 compare

```
问：「我的车被划了吗？」

AI 做的事：
  1. 找出最早和最近两张能看清车的帧
  2. 一起送给 AI 对比
  3. 让 AI 指出差异

**实测已通过（4.8 秒）**：
  {"changed": false, "confidence": 0.95,
   "findings": ["无新增划痕、凹陷、污渍，车窗完好，车门关闭", ...]}
```

### 2.3 归纳类 summarize

```
问：「昨天门口都发生了什么？」

AI 做的事：
  1. 取昨天该设备的所有事件（已带云端摘要）
  2. 归纳成一段话 + 列出重点

成本极低：只发文本，不发图。
```

## 三、成本控制（关键）

### 3.1 用事件库当索引，不扫原始录像

```
笨办法：把 3 天录像逐帧送 AI
  3 天 = 72 小时 = 259200 帧
  按 600 token/帧 = 1.5 亿 token = ¥200+   不可接受

聪明办法：先用本地事件库筛出候选
  3 天该设备事件 = 20 条
  20 帧 = 12000 token = ¥0.02             可接受
```

**本地事件库（YOLO 免费筛出来的）就是索引。**
这就是分层架构的价值：本地负责找候选，云端负责读懂。

### 3.2 逐级细化

```
第一轮：低分辨率缩略图 320px   便宜，先粗筛
第二轮：只对命中的抽高清帧      贵，但候选已很少
```

### 3.3 硬上限

```
每次任务最多检查 20 个候选（可配置）
每批最多 2 帧（图片 token 是大头）
开始前查预算，中途每批再查
结果缓存（同任务同参数不重复花钱）
```

### 3.4 实测单价

```
单帧分析 1024px + JSON   = ¥0.003
查找类任务 20 帧          = ¥0.06
比对类任务 2 帧           = ¥0.005
归纳类任务 纯文本         = ¥0.001
```

**一个任务几分钱。用户按需发起，不是一直跑。**

## 四、AI 开关策略（用户明确要求）

用户说：「设置按钮可以不用一直打开，因为大模型也比较贵」

```
默认：关闭云端（只用本地 YOLO，免费）

三档模式：
  [ ] 只用本地        不花钱，功能受限
  [x] 按需分析        只有你发起任务/点分析时才花钱   <- 推荐（新增）
  [ ] 自动分析        后台自动跑，按策略花钱
```

**新增中间档「按需分析」** —— 能力都在，但不会自己花钱。

## 六、车牌识别（本地 + 第三方）

### 实测数据

同一辆车、同一段录像、不同分辨率：

| 输入 | 读到 | 正确性 |
|---|---|---|
| 1280px 单帧 | 鄂W61J59 | 与人工确认一致 |
| 1024px 对比帧 | 粤W·GL59 | 省份和号码都错 |
| 人工肉眼 2560px | 粤W·6J659 | 也错 |

**结论：通用视觉模型读车牌不可靠，必须专门处理。**

### 三条路线

```
路线 A：本地 LPR 模型（免费、快、离线）
  专门的车牌检测 + 字符识别模型（几 MB）
  需要下载模型（不进 fpk）
  优点：不花钱、不联网、7x24
  缺点：需适配不同车型/角度

路线 B：云端视觉模型（已跑通）
  直接把帧给大模型读
  优点：无需训练、适应性强
  缺点：花钱、不稳定（实测会读错）

路线 C：两者结合（推荐）
  本地 LPR 先读（免费）
  多帧投票（同一车牌读 5 帧取多数）
  格式校验（省简称必须是 31 个合法值）
  低置信度标「待确认」，不当事实
```

### 校验机制（必须做）

```
1. 多帧投票：同一目标读 N 帧，取一致结果
2. 格式校验：省简称 31 个合法值；字母数字组合合法
3. 字符集：排除 I/O 等易混字符
4. 置信度：低于阈值标「待确认」
5. 保留原图，允许人工复核
```

## 七、相似图搜索 -> 目标建档（用户新思路）

用户说：「不一定非要是车吧……比如某个人，或者出现某个事件可以做记录检查」

**理解**：不只是找相似的车，而是**给重复出现的目标建档**。

```
用途 1：某个人            「这个背双肩包的人来过几次？」
用途 2：某件物品          「这个纸箱什么时候出现的？」
用途 3：某个事件模式       「每次快递都在几点？」
用途 4：事件检查           「上周三门口到底有没有人来？」
```

呈现方式变化：

```
旧：上传一张图 -> 找相似的图
新：从事件里选一个目标 -> 建档案 -> 持续收集该目标的出现记录
```

**诚实边界**：

```
车/物：img2vec 有区分度，可用
人形：img2vec 区分度不足（实测）
      要找人应改用云端视觉模型 + 文字描述
      例：「穿深色外套背双肩包的男性」-> 让 AI 逐帧判断
```
