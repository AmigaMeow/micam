# 模型能力边界 —— 从一次车牌误读说起

> 2026-09-17 · 真实事故记录

---

## 一、事故

我在看一张 2560×1440 的监控截图时，声称车牌是「粤W·6J659」。

**实际是「鄂W·61J59」。**

放大到 1360px 后确认：

```
错误 1: 粤（广东）  ->  实际 鄂（湖北）
错误 2: 6J659      ->  实际 61J59
```

### 为什么错

车牌在 2560px 的原图里**只有约 200px 宽**（占宽度 7.8%）。
在这个尺度上，我做的是「猜」而不是「读」—— 但我把猜测当成事实陈述了。

---

## 二、这件事证明了什么

### 2.1 低分辨率下的精细识别不可靠（对人、对模型都一样）

```
原图 2560px  ->  车牌约 200px  ->  勉强能读，易错
缩略图 640px ->  车牌约 50px   ->  人眼也读不出
缩略图 320px ->  车牌约 25px   ->  不可能读出
```

我们把事件缩略图压到 320px 是为了省 CPU ——
**这个尺寸下任何车牌识别都不可能成功**，不是模型问题。

### 2.2 YOLO 不可能输出车牌（不是「弱」，是「没这个类」）

```
COCO 80 类（YOLOv8 的训练集）:
  person / bicycle / car / motorbike / bus / truck / boat /
  bird / cat / dog / ... / toothbrush

没有：车牌、文字、汉字、数字
```

**不在训练类别里的东西，模型永远输出不了 ——
换成 yolov8x（大 10 倍）也一样。**

### 2.3 实测：模型在这张图上做对了吗？

| 模型 | 检出 | 正确性 |
|---|---|---|
| yolov8n | `car` 79% | ✅ 车找对了 |
| yolov8s | `car` 83% + `dog` 32% | ✅ 车对了，**还找到了车后趴着的黄狗** |

**模型完全正确。** 它做的事和人做的事不同 —— 不是同一个任务。

---

## 三、正确的结论

### 3.1 不是「模型太弱」，是「工具不对」

| 任务 | 需要什么 | 状态 |
|---|---|---|
| 人/车/包裹/宠物检测 | YOLO（COCO 80） | ✅ 已有 |
| **车牌定位** | 专门的车牌检测模型 | ❌ 缺 |
| **车牌字符识别** | LPR / OCR 模型 | ❌ 缺 |
| 场景理解（「放下包裹」） | 视觉大模型 | 🔌 接口就绪 |
| 精细文字（门牌/告示） | 视觉大模型 + 高分辨率图 | 🔌 接口就绪 |

**要加车牌：不是换更大的通用模型，是加专门的 LPR 模型。**

### 3.2 任何精细识别都必须有校验

```
车牌识别的正确做法：
  1. 提高分辨率（单独抓高码率关键帧，不用 320px 缩略图）
  2. 多帧投票（同车牌读 N 次，取一致结果）
  3. 格式校验（省简称必须是 31 个合法值之一）
  4. 字符集校验（排除 I/O 等易混字符）
  5. 置信度阈值 + 低置信度标注「待确认」
  6. 保留原图，允许人工复核
```

我连省份字都读错 —— 没有校验的自动化系统会**产生假记录**。

### 3.3 这验证了我们的架构分层是对的

```
本地小模型  ->  快速筛选（人/车/包裹），7×24 免费
外部大模型  ->  场景理解、行为描述
专门模型    ->  车牌/人脸等精细任务（按需增加）
校验机制    ->  所有结果的最后一道关
```

**不要把「精细任务」硬塞给「通用模型」。**

## 四、可以加的能力（按性价比）

| 能力 | 方案 | 成本 | 建议 |
|---|---|---|---|
| 车牌识别 | 本地 LPRNet（~2MB） | 低 | ✅ 值得做 |
| 包裹识别 | 换专门模型 | 中 | 🟡 可选 |
| 场景理解 | DeepSeek 视觉 | 低（¥几/月） | ✅ 值得做 |
| 人脸识别 | face-model（飞牛自带） | 中 + 隐私风险 | ⚠️ 默认关闭 |

---

## 五、教训（写给自己）

```
1. 不确定就说不确定，不要「猜了当事实说」
2. 精细识别前先问「分辨率够吗」
3. 模型的输出范围 = 它的训练类别，不是「它有多强」
4. 任何自动化识别都要有校验和人工复核路径
```
