## 二、会话冲突：**已修复**

你的诊断完全正确：

```
「channel=2 会另起一次 probe 会话，和已有会话冲突导致 cs2: EOF」
```

根因：连接 key 按镜头区分 ——

```go
func connKey(did string, lens int) string {
    if lens >= 2 { return did + "#" + strconv.Itoa(lens) }  // ← 第二镜头用不同 key
    return did
}
```

于是切通道会对**同一台摄像机**建第二条 P2P 会话。
而摄像机一次只接受一条。

修复：建新连接前，先停掉同设备其它镜头的连接，并等 1.2 秒让摄像机释放会话。

**实测对比**：

```
修复前（你测的）: 交替切换  成功 1 / 失败 5
修复后（我实测）: 零延迟交替 10 次  成功 10 / 失败 0
```

日志会记录：`切换镜头：先停掉 N 条同设备连接`

## 三、op=6 / op=13 —— 有结论了

### op=6 的语义

按你的建议测了「op=6 前后对比位置」：

```
op=6 之前:   angle=95
发送 op=6:   返回 {"angle":0,"elevation":0,"ret":0}
立刻读:      angle=98
5 秒后:      angle=100（到极限，ret=-1001）
```

**既没归零，也没停住。** 所以 op=6 的语义仍然不明 ——
它返回 ret=0（唯一），但不读位置、不停止、不复位。
可能是某种「确认/心跳」类命令。

### op=13 绝对定位：**确认不可用**

```
op=13 + {angle,elevation}  -> 参数被忽略（按步进处理）
op=13 + {pan,tilt,...}     -> 摄像机断连（字段白名单拒绝）
```

你的「字段白名单比参数组合更重要」这条判断很准。
堆参数组合效率确实低。

## 四、**绝对定位的替代方案：已实现**

虽然 op=13 不可用，但我从步进实测里找到了可行方案。

### 关键数据：步长很稳

```
连续发送 op=2（左）：
100 -> 97 -> 94 -> 91 -> 89 -> 86 -> 83 -> 80 -> 78 -> 75 -> 72 -> 69 -> 67 -> 64 -> 61 -> 59 -> 56 -> 53 -> 51
平均每步 -2.7°
```

### 方案：**读数 + 步进闭环**

```
保存预置位：{slot} -> 读当前 (angle, elevation) 存盘
调用预置位：
  loop (最多 40 步):
    读当前位置
    计算 delta = target - current
    |delta| <= 1° -> 完成
    发送方向指令（op=2/5 转角度，op=3/4 转仰角）
    等 700ms 让它转完
    重新读数（关键：指令响应是移动**前**的位置，滞后一拍）
```

### 新接口

```
GET    /api/ptz/preset?did=X         列出所有预置位
POST   /api/ptz/preset {did,slot,name?}   保存当前位置到槽位（最多 9 个）
DELETE /api/ptz/preset?did=X&slot=N  删除
POST   /api/ptz/goto   {did,slot}    调用（闭环步进）
```

`goto` 的响应会带上进度：

```json
{
  "ok": true,
  "steps": 3,                      // 走了几步
  "current": {"angle":56,"elevation":61,"ret":5},
  "target":  {"slot":1,"angle":56,...},
  "delta":   {"angle":0,"elevation":0}
}
```

**这解决了你提的「从极限挪回中间要 30+ 条指令」的问题** ——
客户端只需调一次 `goto`，服务端跑闭环。

> ⚠️ 单次 `goto` 可能需要 10-30 秒（取决于距离），
> 请把 HTTP 超时设到 **60 秒以上**，或做成异步 + 轮询。

## 五、关于护栏：ack 里的 ret 不能当成功判据

我这边也确认了：**`ret` 因机型和状态而异**：

```
CW300 正常   ret=0
CW500 正常   ret=5
到达极限     ret=-1001
```

**客户端不要判 `ret==0`**，会误判。
判断成功应该看：操作后的位置是否朝预期方向变化。
