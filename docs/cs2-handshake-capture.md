## 二、每个包的原始字节（照这个实现）

### ① 局域网搜索包（NAS -> 32108）

~~~
IP 192.168.1.100.36857 > 192.168.1.10.32108: UDP, length 4
4500 0020 9fe8 4000 4011 162e c0a8 0264   <- IP 头
c0a8 0102 8ff9 7d6c 000c 84d4             <- UDP 头（源 36857 目的 32108）
f130 0000                                  <- ★ 载荷 4 字节
~~~

**载荷**：`f1 30 00 00`
- `f1` = magic
- `30` = msgLanSearch
- `00 00` = 保留

**目标**：`<摄像头IP>:32108`（固定端口）
**源端口**：随机（本例 36857）

### ② 摄像头 punch 回应（32108 -> NAS）

~~~
192.168.1.10.26612 > 192.168.1.100.36857: UDP, length 24
f141 0014 584d 5359 434e 4c00 0007 6ea7 4d4b 4d4e 4e00 0000
~~~

**解析**：
~~~
f1 41              <- magic + msgPunchPkt(0x41)
00 14              <- size = 20
584d 5359 434e 4c   "XMSYCNL"   <- 固定标识
00 00 07 6e a7 4d 4b 4d 4e 4e   <- 设备信息
00 00 00
~~~

**关键**：摄像头从 **26612** 端口回应（这是它的 P2P 端口，动态分配）

### ③ NAS 回 punch（NAS -> 26612）

~~~
192.168.1.100.36857 > 192.168.1.10.26612: UDP, length 24
f141 0014 584d 5359 434e 4c00 0007 6ea7 4d4b 4d4e 4e00 0000
~~~

**注意**：载荷和 ② **完全一样**（原样回显）

### ④ P2P 就绪（26612 -> NAS，len=48）

~~~
192.168.1.10.26612 > 192.168.1.100.36857: UDP, length 48
f143 002c 584d 5359 434e 4c00 0007 6ea7 4d4b 4d4e
4e00 0000 0002 f467 0201 a8c0 0000 0000
0000 0000 0000 0000 0000 0000
~~~

**关键字段**：
~~~
f1 43              <- magic + msgP2PRdyTCP(0x43)   ★ 告诉客户端用 TCP
00 2c              <- size = 44
584d 5359 434e 4c   "XMSYCNL"
00 00 07 6e a7 4d 4b 4d 4e 4e 00 00 00
00 02 f4 67        <- 端口相关（注意字节序）
02 01 a8 c0        <- ★ IP 192.168.1.10（小端：c0 a8 01 02 反序）
00 ...             <- 填充
~~~

**注意 `02 01 a8 c0`**：这是 IP 的**小端**表示，
反过来读 `c0 a8 01 02` = 192.168.1.10。

**go2rtc 的注释里有一行被注释掉的代码**：
~~~go
//host := fmt.Sprintf("%d.%d.%d.%d:%d", b[31], b[30], b[29], b[28], uint16(b[27])<<8|uint16(b[26]))
~~~
说明它本来想从包里解析 IP，后来改成直接用 `conn.RemoteAddr()`。

### ⑤ 建 TCP 连接

~~~
NAS:51948 -> 192.168.1.10:26612  TCP SYN
~~~

**目标端口 = 摄像头回 punch 的源端口（26612）**，不是 32108。

### ⑥⑦ 认证（TCP 上）

~~~
NAS -> 摄像头: TCP len=209   （认证请求）
摄像头 -> NAS: TCP len=12    （认证响应）
~~~

认证内容就是 `{"public_key":...,"sign":...,"uuid":"","support_encrypt":0}`。

## 三、给 Mac 的实现要点

### 3.1 最容易错的地方

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | 搜索包发到错端口 | 必须是 **32108** |
| 2 | 搜索包内容错 | 必须 **4 字节**：`f1 30 00 00` |
| 3 | 没等 punch 回应 | 要**循环重发**搜索包直到收到 `0x41` |
| 4 | 用 32108 建 TCP | TCP 要连**摄像头回 punch 的源端口** |
| 5 | 没回 punch | 收到 `0x41` 后要**原样回显**给摄像头 |
| 6 | 直接建 TCP | 必须等 `0x43`(P2PRdyTCP) 才能建 |

### 3.2 关键代码逻辑（伪代码）

~~~
// 阶段 1：搜索
sock = UDP()
sock.bind(random_port)
for i in 0..N {
    sock.send_to("<cam_ip>:32108", [0xf1, 0x30, 0x00, 0x00])
    resp = sock.recv(timeout=1s)
    if resp[1] == 0x41 { break }   // 收到 punch
}

// 阶段 2：回 punch（关键！很多人漏了这步）
cam_p2p_port = resp.src_port          // 本例 26612
sock.send_to("<cam_ip>:" + cam_p2p_port, resp.payload)  // 原样回显

// 阶段 3：等 P2P 就绪
for i in 0..N {
    resp2 = sock.recv(timeout=1s)
    if resp2[1] == 0x43 { break }  // TCP 就绪
    if resp2[1] == 0x42 { /* UDP 就绪 */ }
}

// 阶段 4：建 TCP
tcp = TCP.connect("<cam_ip>:" + cam_p2p_port)   // 注意端口

// 阶段 5：认证
tcp.send(auth_json)
resp = tcp.recv()
~~~

### 3.3 消息类型速查

| 值 | 名称 | 方向 |
|---|---|---|
| `0xf1` | magic | - |
| `0x30` | msgLanSearch | 客户端 -> 摄像头 |
| `0x41` | msgPunchPkt | 摄像头 -> 客户端 |
| `0x42` | msgP2PRdyUDP | 摄像头 -> 客户端 |
| `0x43` | msgP2PRdyTCP | 摄像头 -> 客户端 |
| `0xd0` | msgDrw | 双向（数据） |
| `0xd1` | msgDrwAck | 双向 |
| `0xe0` | msgPing | 客户端 -> 摄像头（TCP 每秒） |
| `0xe1` | msgPong | 摄像头 -> 客户端 |
| `0xf1` | msgClose | - |

## 四、关于「WiFi vs 有线」

**这次抓包有个重要发现**：

NAS 的 UDP 搜索包是**单播**（unicast），不是广播：

~~~
NAS:36857 -> 192.168.1.10:32108   ← 直接发给摄像头 IP
~~~

**不是** `255.255.255.255` 广播。

**这意味着**：
- 不需要 AP 转发广播/组播
- 只要 UDP 单播能出去就行
- **WiFi 和有线在这点上没有区别**

**所以我还是认为「插网线」不是根因**，但成本低，值得一试。

### 更可能的原因（按概率排序）

| 可能 | 验证方法 |
|---|---|
| **Mac 防火墙拦出站 UDP** | 系统设置 → 网络 → 防火墙 → 关闭测试 |
| **搜索包没重发** | 检查代码是否循环重发（UDP 会丢包） |
| **漏了「回 punch」步骤** | 对照上面 3.2 的伪代码 |
| **TCP 连错端口** | 必须连摄像头回 punch 的源端口 |
| **超时太短** | 建议每个阶段至少 5 秒 |
