## 一、为什么必须先做机位检查

补测时发现的真实案例：

```
CW500（双摄版）的录像里有车
但当前实时缩略图是瓷砖墙和对联

原因：双摄有两个镜头，走的是不同画面
另有 PTZ 云台可能被转动
```

**不做检查就比对，「有变化」可能只是机位变了 —— 会给出完全错误的结论。**

---

## 二、机位元数据（已实现）

```
GET  /api/camera/pose            列出各设备最后一次机位快照
POST /api/camera/pose/capture    记录当前机位 {did, lens}
```

每条快照记录：

```json
{
  "did": "1149106927",
  "device": "小米室外摄像机CW500双摄版",
  "lens": 1,                  // 镜头编号（双摄：1/2）
  "angle": 87,                // PTZ 水平角（读不到为 -9999）
  "elevation": 69,            // PTZ 俯仰角
  "hasPtz": true,
  "takenAt": "2026-09-17 16:30:00",
  "fingerprint": "a3f2c190"  // 画面粗指纹（FNV-1a）
}
```

## 三、一致性判定规则

```
镜头不同          -> 不可比（双摄走不同画面）
PTZ 角度差 > 3°   -> 不可比
画面指纹不同      -> 可比，但提示「建议人工确认」
                     （指纹不同也可能是场景本身变了）
```

**阶段 3 才真正启用这个闸门**；本阶段先把元数据定义并记录下来。

## 四、基线测试框架

### 4.1 为什么不能用合成样本

实测教训（见 AI-CHANGE-DETECTION-TEST.md）：

```
用 PIL 合成的「划痕」「开门」「贴纸条」全部被模型判定为
「图像伪影 / 图像层面的遮盖」，返回 changed:false。

**模型的判断是对的** —— 合成痕迹（笔直的线、纯色矩形、跨过车牌）
在视觉上就明显不是物理损伤。

结论：合成样本无法用于测试这个能力，必须用真实发生的变化。
```

### 4.2 真实样本从哪里来

```
来源 1：录像里的真实事件前后帧（最实用）
  · 车进出：有车 -> 无车
  · 包裹送达：地上无 -> 有包裹
  · 人员经过：无人 -> 有人 -> 无人
  · 车门开合（真实物理动作）

来源 2：同一机位、不同日期的同场景
  · 需要 PTZ 每次回到预置位
  · 或固定机位摄像头

来源 3：用户主动上报
  · 「我的车昨天被蹭了」-> 用户提供真实损伤案例
  · 这是最有价值的样本，但需要用户参与
```

### 4.3 样本集结构

```json
{
  "id": "real-001",
  "kind": "compare",
  "before": "/path/before.jpg",
  "after": "/path/after.jpg",
  "officialChange": false,      // 真实答案（人工标注）
  "changeType": "none",         // none / vehicle / environment
  "note": "同一机位相隔 10 秒",
  "pose": { "lens": 1, "angle": 87, "elevation": 69 }
}
```

### 4.4 必测分组（沿用评审建议）

| 分组 | 说明 | 期望 | 样本数 |
|---|---|---|---|
| A 无变化对照 | 同一机位短时间 | changed=false | ≥8 |
| B 真实车辆变化 | 车进出/门开合/异物附着 | changed=true | ≥8 |
| C 干扰变化 | 光线/影子/雨迹变化，车未变 | changed=false | ≥8 |
| D 长时间跨度 | 间隔数天 | 观察准确率衰减 | ≥6 |

### 4.5 判定指标

```
准确率   = (A正确 + B正确 + C正确) / (A+B+C总数)
漏报率   = B组判成 false 的比例     <- 最不能接受
误报率   = A+C 组判成 true 的比例

**零容忍项**：证据编造（返回的时间/图片与实际内容对不上）
```

### 4.6 门槛（先测基线，不预设理想值）

```
第一轮：跑 30+ 组，记录准确率/漏报率/误报率
第二轮：根据基线调 prompt 与置信度阈值
第三轮：达标才上线（建议漏报率 < 20%，误报率 < 15%）

confidence < 0.6 -> 前端标「不确定，建议人工确认」
                    不给「没有」这种确定结论
```
