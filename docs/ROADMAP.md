# MiCam 功能与页面规划

> 版本：v0.18.0 · 2026-09-16
>
> 本文档供**设计效果图**使用。每节包含：页面目标、内容区块、交互、
> 数据来源（哪些小米有、哪些要自己做）。

---

## 零、产品定位

**家庭 NAS 监控中心** —— 在飞牛上统一管理小米摄像头。

~~~
看实时  ->  知道发生了什么  ->  回看/取证  ->  管好存储
~~~

**明确不做**：设备控制（开关灯/空调等 MIoT）—— 用户明确要求不做。

### 1.2 导航形态（二选一，请在设计稿里定）

**方案 A：左侧边栏**（当前实现）
~~~
优点：页面多时更清晰，像后台管理
缺点：占横向空间
~~~

**方案 B：顶栏横排**（效果图那样）
~~~
优点：更像桌面 App，留出更多内容宽度
缺点：入口超过 6 个会挤
~~~

> 建议：**主入口 5 个放顶栏，次级入口（账号/设置/开发者）收进右上角头像菜单。**

**目标**：打开就知道「家里现在什么情况」。

~~~
┌─ 顶部：3 个大数字 ────────────────────────┐
│  在线摄像头 2/3      今日事件 14      存储 72.7%  │
└──────────────────────────────────────────┘

┌─ 摄像头（横向卡片，点进实时）─────────────┐
│  [画面]        [画面]        [离线]        │
│  门口 13:27    后院 13:27    车库 --       │
└──────────────────────────────────────────┘

┌─ 最近事件 ────────────┬─ 存储 ──────────┐
│ ● 13:25 门口 有人      │ [进度条]        │
│ ● 13:12 后院 移动      │ 已用 300GB      │
│ ● 12:48 门口 车辆      │ 可录约 125 小时 │
│            [查看全部]  │ [清理] [设置]   │
└───────────────────────┴─────────────────┘
~~~

| 区块 | 内容 | 数据来源 |
|---|---|---|
| 概览数字 | 在线数 / 今日事件 / 存储占比 | 设备列表 + 事件库 + 存储接口 |
| 摄像头行 | 缩略图 + 名称 + 最新时间 | `/api/live/thumb` |
| 最近事件 | 5 条最新事件 | **需新建事件库** |
| 存储卡 | 进度条 + 可录时长 | `/api/storage` |

**交互**：点摄像头 → 实时预览；点事件 → 回放该时刻；点「查看全部」→ 事件中心。

### 3.6.2 每个事件包含

| 字段 | 说明 | 来源 |
|---|---|---|
| 时间 | 精确到秒 | 侦测时记录 |
| 设备 | 哪台摄像头 | |
| 类型 | 移动 / 有人 / 车辆 / 离线 / 上线 | **移动自己算；人形/车辆需要 AI 或摄像头支持** |
| 缩略图 | 事件瞬间的帧 | 抓拍 |
| 时长 | 持续多久 | 侦测区间 |
| 录像位置 | 对应哪个录像文件 + 时间偏移 | 便于回放 |

### 3.6.3 数据来源（重要）

**小米 API 不提供事件流**（我们验证过 MIoT 不支持摄像头）。
所以有三种做法：

| 方案 | 原理 | 准确度 | CPU | 建议 |
|---|---|---|---|---|
| **A. 帧差侦测** | 定时抓帧比对 | 中 | 低 | ✅ **首选** |
| B. ffmpeg 场景检测 | 持续解码 + scene 滤镜 | 高 | 高 | 备选 |
| C. 逆向 P2P 事件 | 解析摄像机主动上报 | 最高 | 最低 | 工作量大 |

**方案 A 细节**：
~~~
每台在线摄像头每 5 秒抓一张 320px 小图（走已有的缩略图缓存）
   -> 与上一张做像素差
   -> 差值超阈值 => 记一条「移动」事件
   -> 连续触发时合并成一段（避免刷屏）
~~~

**人形/车辆识别**：需要 AI 模型（见 3.9），初期只做「移动」。

## 四、需要新做的后端能力

页面的地基是后端。**以下 4 项是新增功能**，其余页面用现有接口就能做：

### 4.1 移动侦测（事件中心的根基）

~~~
频率：每台在线摄像头每 5 秒一次（复用缩略图缓存，几乎零额外开销）
算法：320px 灰度图 + 帧差 + 阈值
输出：事件 {time, did, type:'motion', thumb, duration}
去重：连续触发合并成一段（间隔 < 30 秒视为同一事件）
~~~

**可靠度**：
~~~
✅ 能检测：有人走过、车开过、光线突变（需过滤）
⚠️ 误报：树影、雨雪、夜间红外切换
   -> 需要「灵敏度」调节 + 白天/夜间不同阈值
~~~

### 4.2 事件库（持久化）

~~~
存储：events.jsonl（追加写，按天分文件）
字段：id, time, did, type, thumbPath, duration, recFile, recOffset
容量：自动清理（默认保留 90 天）
查询：按时间/设备/类型过滤 + 分页
~~~

### 4.3 设备别名与分组

~~~
存储：devices.json（did -> {alias, aliasEn, group, favorite}）
分组：自定义（效果图的 Outdoor/Indoor/Favorites 只是示例）
~~~

### 4.4 云台预置位（可选）

~~~
存储：presets.json（did -> [{name, angle, elevation}]）
实现：保存当前位置 / 一键回到保存位置
需先确认 cs2 协议是否支持「绝对位置」指令
~~~

## 六、开发阶段规划

### 阶段 1：补齐核心体验（建议先做）

~~~
1. 首页/总览        ← 新页面
2. 摄像头列表打磨    ← 别名/分组/最后活动/卡片操作
3. 实时预览补全      ← 全屏/比例/预置位
4. 多路预览补全      ← 布局/拖拽/轮巡
~~~

### 阶段 2：事件体系（产品价值最大）

~~~
5. 移动侦测（后端）
6. 事件库（后端）
7. 事件中心（前端）  ← 核心页面
8. 回放页重构（时间轴事件标记 + 日历 + 倍速）
~~~

### 阶段 3：管理与打磨

~~~
9. 摄像头详情页
10. 系统设置补全（主题/语言/通知细化）
11. 存储趋势图 / 迁移
~~~

### 阶段 4：AI（可选）

~~~
12. AI 调查（事件库之上的自然语言查询）
13. 人形/车辆识别（需图像模型）
~~~
