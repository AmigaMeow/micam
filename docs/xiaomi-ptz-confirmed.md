# 云台方向 — CW500 实测确认（第三版）

> 2026-09-16 | 限流恢复后复测
> 设备：**CW500**（isa.camera.hlmax，**真机械云台**）
> 方法：相位相关（含合成位移自检）

---

## 一、为什么用 CW500 而不是 CW300

| 设备 | 云台类型 | 数据质量 |
|---|---|---|
| CW300 | **存疑**（不支持 MIoT 6.12） | 方向在多次运行中不一致 |
| CW500 | **真机械云台**（支持 MIoT 坐标） | **一致** |

CW500 的 angle/elevation 回读真实反映物理位置，所以用它定标准。

---

## 二、CW500 实测数据

自检：`np.roll(base,30,axis=1)` -> `dx=+30` ✅

~~~
op    dx      dy      angle 变化      elevation 变化
----  ------  ------  ------------    --------------
2     +26      0     几乎不变        不变
3     +35    +43     90->94, 99->100  81->89, 89->98
4       0    -77     不变             92->82
~~~

### 2.1 结论

~~~
op=2  dx=+26  ->  画面内容右移  ->  视野向左   =>  op=2 = 左
op=3  dy=+43  ->  画面内容下移  ->  视野向上   =>  op=3 = 上
op=4  dy=-77  ->  画面内容上移  ->  视野向下   =>  op=4 = 下
~~~

**三个都符合当前插件映射。**

### 2.2 关于 op=3 的 dx=+35

op=3 同时有 dx=+35 和 dy=+43，看起来像「斜向」。
但读数是 elevation 显著增加（+8），angle 只 +4。

**判断**：op=3 是「上」，dx 是镜头仰起时画面透视变化引起的伪位移。
（相机上抬时，近处物体在画面中的位置会横向漂移）

## 四、回读值的坑

### 4.1 不同设备返回不同的 ret

| 设备 | ret |
|---|---|
| CW300 | `0` |
| CW500 | `5`（正常移动时） |
| CW500（到达极限） | `-1001` |

**所以不要用 ret==0 判断成功。** 用画面位移或 ret>=0。

### 4.2 CW500 到极限时

~~~
angle=100（最大值）时继续按「左/右」-> ret=-1001
~~~

客户端应处理这种情况（提示「已到极限」而不是「失败」）。

---

## 五、CW300 的不一致（仍未解）

CW300 上 op=2 在不同运行中 dx 符号相反：

| 运行 | 起始位置 | dx |
|---|---|---|
| A | angle=100 | -31, -34 |
| B | angle=36-47 | +21, +22, +22, +21, +18 |

两次标准差都只有 1.5-2，不是噪声。

**可能原因**：
1. CW300 不是真机械云台（电子裁切/派生能力）
2. op=2 在某固件上是「回到预设位」语义

**建议**：CW300 云台用「翻转开关」适配，不要写死方向。

## 六、给 Mac 的结论

### 6.1 映射可以定了

~~~swift
enum PTZOp: Int {
    case query = 1
    case left  = 2
    case up    = 3
    case down  = 4
    case right = 5
}
~~~

**不需要默认翻转。** 之前的困惑来自 CW300 的不一致行为。

### 6.2 仍需注意

1. **不要用 ret==0 判断成功**（CW500 正常时 ret=5）
2. **CW300 保留翻转开关**（它的行为不规则）
3. **极限位置**（angle 0/100）时操作会返回 -1001
4. **同一设备同时只有一路 cs2 连接**（云台会短暂占用视频通道）

### 6.3 关于 Mac 之前的测量

Mac 测到 op=2 -> 画面内容左移（视野向右），
我在 CW300 和 CW500 上都测到内容右移（视野向左）。

**CW500（真机械云台）的数据支持我的结论** —— op=2 = 左。
建议 Mac 复核相位相关的符号自检。
