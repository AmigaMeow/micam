## 二、CW500 的问题：真正原因是 cs2 凭据过期

**不是会话复用问题。**

日志证据：

~~~
[1000000101] 缓存凭据已 24h0m0s，重新申请
runFFmpeg 失败: 向小米云申请凭据失败: code=-12 msg=throttle deny
~~~

**根因链**：

~~~
1. cs2 凭据（sign/device_public）有有效期（实测 8+ 小时后失效）
2. 我的代码之前无条件信任缓存
3. 凭据失效 -> auth failed -> 流建不起来
4. 我加了刷新逻辑，但刷新时撞上小米云限流
5. 刷新失败 -> 连旧凭据也被清了 -> 彻底不可用
~~~

**为什么截图能用**：截图路径有重试，可能碰巧拿到新凭据。

**正在修**：
- 刷新失败时**回滚到旧凭据**（不清空）
- 刷新加 **10 分钟冷却**（避免限流）
- 只在 auth 真失败时才刷新

## 三、关于你发现的 Apple 侧坑

**CFNetwork 读不了 multipart/x-mixed-replace** —— 这个发现很有价值。
你的解决方案（裸 socket + 手动切帧）是**正确做法**。

**补充两点**：
1. MJPEG 响应头是 boundary=mjpegframe（v0.3.3 后统一了）
2. 每帧都带准确 Content-Length，可按长度切，不必只靠 FFD8FF/FFD9

## 四、v0.5.0 新增：HLS 播放（2K 流畅）

**重要** —— 如果用 MJPEG 遇到性能问题，试 HLS：

~~~
GET /api/live/hls?did=xxx&fps=15&w=0     # w=0 表示 2K 原画
GET /api/live/hls?did=xxx&seg=seg0.ts    # 下载分片
~~~

**实测对比**（NAS 是 Intel J4125）：

| 方案 | CPU | 首帧 | 数据量 |
|---|---|---|---|
| MJPEG 2K | 335% | 9-19s | 49.8 MB |
| **HLS 2K** | **94%** | **8s** | 17.5 MB |

**播放方式**：
- Safari：原生 <video> 直接播
- 其他：hls.js
