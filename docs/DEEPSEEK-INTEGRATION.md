## 二、三个关键技术点（踩过的坑）

### 2.1 这是**推理模型**：content 可能为 null

```json
{
  "choices": [{
    "message": {
      "content": null,                    ← 答案字段为空
      "reasoning_content": "我们需要回答用户。用户说..."   ← 思考在这里
    },
    "finish_reason": "length"             ← 思考没完就截断了
  }]
}
```

**`max_tokens` 必须给足**：

| max_tokens | 结果 |
|---|---|
| 50 | content = null（全被思考吃掉） |
| 100 | content = null |
| 1500 | ✅ 正常返回 |

短任务的思考也要 200~500 token，所以**最小值建议 1024**。

### 2.2 JSON 输出会被 ``` 包裹

即使设了 `response_format: {"type":"json_object"}`，返回仍是：

````
```json
{"summary": "...", "objects": [...]}
```
````

**解析前必须剥掉代码围栏**，否则 JSON.parse 失败。

### 2.3 图片用 base64 data URL

```json
{"type": "image_url", "image_url": {"url": "data:image/jpeg;base64,..."}}
```

1280px 宽的图约 590 prompt token。**建议压到 768~1024px** 平衡精度与成本。

## 三、视觉能力实测（关键验证）

### 测试：读车牌

同一张 1280px 监控截图，三种方式对比：

| 方式 | 结果 | 说明 |
|---|---|---|
| 我肉眼（2560px 原图） | `粤W·6J659` ❌ | 猜的，省份和号码都错 |
| 我肉眼（放大 1360px） | `鄂W·61J59` ✅ | 放大后才看清 |
| **yolov8n（本地）** | `car 79%` | **COCO 无车牌类，永远给不出号码** |
| **deepseek-v4.1-flash** | **`鄂W61J59`** ✅ | **一次就对** |

模型的思考过程（`reasoning_content`）：

```
哦，我需要提取图中的文字内容。这张图是一个室外监控画面，
画面中央停着一辆深色轿车，车牌位于车头正下方。
车牌是蓝底白字，清晰可见，没有遮挡或模糊。
从左到右依次是：汉字「鄂」、字母「W」...
```

**它先定位车牌，再判断颜色/清晰度，最后逐字识别** —— 这是真正的"读懂"，
而不是像 YOLO 那样只能输出固定的 80 类之一。

### 测试：JSON 结构化输出

输入：「一个监控画面里有人放下包裹后离开」

输出：

```json
{
  "summary": "监控画面中一名人员放下包裹后离开现场。",
  "objects": ["人员", "包裹", "监控画面"],
  "actions": ["放下包裹", "转身离开"]
}
```

**可以直接映射到我们的事件字段**：

```
aiSummary  <- summary
aiEntities <- objects
aiActions  <- actions
```

## 四、成本

实测 token 用量：

| 任务 | prompt | completion | 合计 |

按 DeepSeek Flash 官方价（$0.15/$0.60 每 1M）估算：

```

每天 20 条事件          ≈ ¥0.03/天  ≈ ¥0.9/月
每天 100 条事件         ≈ ¥0.15/天  ≈ ¥4.5/月
```

**一个月几块钱。**

## 五、设计结论

### 5.1 分层是必要的，不是优化

```
本地 YOLO      ->  筛选（有人/有车）        快、免费、7x24
                但「看到什么」能力有限（固定 80 类）

视觉大模型      ->  理解（谁、在做什么、拿的什么）
                能读文字/车牌/门牌，能给行为描述
                但慢（3 秒）、要钱、要联网

规则引擎        ->  决定「什么时候值得花这个钱」
```

**车牌这种精细任务，本地小模型做不到，不是它弱，是工具不对。**

### 5.2 关键实现要求

```
1. max_tokens 默认 1024，视觉任务 1536
2. 解析时剥掉 ```json 围栏
3. 读 content，空则读 reasoning_content 末尾（兜底）
4. 图片压到 1024px 再上传
5. 结果缓存（SHA256(图) + model + prompt 版本）
6. 记账：token 数 -> 费用
7. **API Key 只存后端，不下发前端**
```
