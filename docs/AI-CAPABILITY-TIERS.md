### 🟡 B 级：能做，但有代价或限制

| 能力 | 限制 | 建议 |
|---|---|---|
| **相似图搜索** | img2vec 单张 3.75s | 只在用户主动搜索时跑，不做后台 |

### 🔴 C 级：现在做不到，如实告知

| 能力 | 为什么做不到 |
|---|---|
| **跨摄像头人体 Re-ID** | 需要专门的 ReID 模型（没有），img2vec 精度不够且慢 |
| **实时视频理解** | 只能关键帧（成本+带宽），做不到逐帧 |
| **本地车牌 OCR** | 无 OCR 模型，装不了 tesseract（PEP 668） |
| **人脸身份识别** | 技术上可行（face-model），但**敏感 + 需用户明确授权**，默认不做 |
| **本地 LLM** | 没有 torch/transformers，跑不了 |
| **24h 连续视频分析** | 4 核 CPU 算不动（yolov8n 256ms/帧 → 24h 需 22 小时） |
| **实时视频上传** | 带宽 + 成本都不现实 |

## 四、推荐架构（务实版）

```
摄像头流
   ↓
【帧差侦测】已有，零成本
   ↓
【本地目标检测】yolov8n 256ms  ← 已有（v0.25.0）
   输出: person / vehicle / 其它
   ↓
【事件库】已有，结构化存储
   ↓
【规则引擎】决定「值得进一步分析吗」
   · 深夜 + 门口 + 有人   → 是
   · 白天 + 车道 + 车辆   → 否（省成本）
   · 同一目标 30 秒内重复 → 合并
   ↓
【外部视觉理解】deepseek-flash  ← 待实现
   输入: AI 事件包（4-8 张关键帧，带时间戳）
   输出: 结构化 JSON（summary / entities / actions / tags）
   ↓
【事件增强】写回事件库  ← 待实现
   ↓
───────────────────────────────────
   查询 / 调查 / 摘要 / 告警 / 自动化
```

**关键原则**：

```
便宜、实时、重复  →  本地（帧差 + 目标检测）
复杂、偶发、理解  →  外部（视觉大模型）
搜索、统计、过滤  →  本地（事件库 + faiss）
```

## 五、你提的 8 类 AI 能力，逐条裁定

| # | 你的设想 | 裁定 | 理由 |
|---|---|---|---|
| 1 | 基础检测（人/车/宠物/包裹） | 🟢 **已有** | yolov8n 已跑通 |
| 2 | 事件筛选（过滤无意义录像） | 🟢 **能做** | 规则引擎 + 本地检测 |
| 3 | 场景理解（「放下了一个包裹」） | 🟢 **能做** | deepseek-flash 视觉 |
| 4 | 自然语言搜索 | 🟢 **能做** | LLM 解析 + 事件库过滤 |
| 5 | 事件摘要（日/周报） | 🟢 **能做** | 每日 1 次 LLM，成本几毛 |
| 6 | 异常判断（停留/反复出现） | 🟡 **部分能做** | 停留时长可算；「反复出现」需 ReID |
| 7 | 跨事件调查（同一辆车多次） | 🟡 **车可行，人困难** | 车的 embedding 相对稳定；人需 ReID 模型 |
| 8 | 主动提醒 | 🟢 **能做** | 规则 + 二次确认 |

### 特别说明第 7 条（跨事件调查）

```
车：img2vec 对车的 embedding 相对稳定（颜色/车型/角度变化小）
    实测相似度 0.98 / 0.89，有区分度
    → 可以做「找相似的车」，但需人工确认

人：img2vec 对 224x224 的整个人形 embedding 区分度很低
    （衣着/姿态/角度变化大）
    → 做不了可靠的「找同一个人」
    → 要做得用专门的 Person ReID 模型（没有）
```

**所以「找相似的车」能做，「找同一个人」不能做** —— 这是我如实告诉你的。
