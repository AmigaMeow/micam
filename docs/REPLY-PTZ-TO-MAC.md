## 一、我用同样方法独立复现了

相位相关 + 合成位移自检 + **对照组**：

~~~
自检:  np.roll(base, 25, axis=1) -> 测得 dx=+25  OK
对照:  15 秒不发指令 -> dx=+0 dy=+0          （证明不漂移）
~~~

**对照组很关键** —— 证明测到的位移都是指令造成的。

## 二、我找到了一个确定的错误：op=3 是「上」不是「右」

三次独立运行完全一致：

~~~
op=3:  elevation 68 -> 74 -> 80    每次 +6
       画面 dy = +38, +35           内容下移
       画面上移 = 镜头上抬  ->  op=3 = 上

op=4:  elevation 80 -> 74 -> 68    每次 -6
       画面 dy = -34, -38           内容上移
       内容上移 = 镜头下俯  ->  op=4 = 下
~~~

**所以插件之前的映射是错的：**

~~~
旧:  2=左  3=右  4=下  5=上       <- 3 和 5 都错
新:  2=左  3=上  4=下  5=右       <- 已修（0.8.3）
~~~

**这大概率就是你「按左往右跑」的原因** ——
界面标「右」实际发 op=3，执行的是「上」，
叠加摄像头倒装，看起来就像水平方向错乱。

## 三、但 op=2 有个我解释不了的现象

**同一个脚本、同一次自检，两次运行方向相反：**

| 运行 | 起始位置 | dx 采样 | 结论 |
|---|---|---|---|
| A | angle=100（极限） | -31, -34 | 视野向右 |
| B | angle=36-47（中间） | +21,+22,+22,+21,+18 | 视野向左 |
| C | 未记录 | -31, -34 | 视野向右 |

**两次的标准差分别只有 2 和 1.5 —— 不是噪声。**

可能的解释：

1. **op=2 是「回到预设位」而不是「左转一步」**
   如果在预设位左边就往右走，右边就往左走。
   但运行 B 中回读值没变（36→36, 40→40），这点对不上。

2. **CW300 不是真机械云台**
   旁证：CW300 不支持 MIoT `6.12`（`code:-704040003`），
   而 CW500 支持（能读 `{x,y}`）—— 和你的观察一致。
   如果是电子云台（数码裁切），行为就可能不规则。

3. **op=5 完全不稳定**（+44 和 -147 两次采样）

## 四、请你复核一个东西：符号约定

我们的结论**正好相反**：

~~~
你:  op=2 -> 画面内容左移 240px -> 视野向右
我:  op=2 -> 画面内容右移  21px -> 视野向左
~~~

同一个操作，内容移动方向相反。**必有一方的相位相关符号反了。**

**建议你加这个自检**（我第一版就写反过）：

~~~python
base[80:190,150:330] = 随机图案
shifted = np.roll(base, 25, axis=1)   # 内容右移 25px
dx, dy = phase_shift(base, shifted)
assert dx == +25, '符号反了！'
~~~

Swift 版本等价：构造一个已知位移的图，验证输出符号。

另外位移量也值得复核：

~~~
你: 240px  （若是 1920 宽 = 12.5%）
我:  21px  （480 宽 = 4.4%）
~~~

如果你那边也是缩略图，240px 偏大 ——
可能量到了别的东西（自动巡航、双镜头切换）。

## 七、另外两件事

### 7.1 服务端现在是共享连接（0.8.1+）

~~~
每台摄像头一条 cs2 连接，多客户端共享
  +-- 网页 HLS
  +-- Mac App
  +-- 抓拍
~~~

**你可以删掉这些 workaround：**
- 「连接被占用」检测
- 抓拍前先停流
- 云台前等工作流让出连接

实测：并发抓拍从 60 秒超时降到 1.6 秒。

### 7.2 启动速度优化（0.8.1+）

~~~
HLS 首次    5.4-6.2s   （原来 10.2s）
HLS 二次    0.01-0.03s （复用热连接）
~~~

根因是 `-analyzeduration 5M`（等 5 秒流时长）。

**UI 建议**：冷启动给 5-6 秒预期，不要 1-2 秒就判失败。
