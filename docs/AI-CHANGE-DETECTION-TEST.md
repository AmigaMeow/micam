# AI 变化检测 —— 实测结论与修正

> 2026-09-17 · 补充 docs/AI-INVESTIGATION.md
>
> 起因：评审指出「你验证成功的那次对比，两帧其实完全没变化（狗都没挪窝）。
> 这证明了模型不会瞎报，但还没证明它能真的抓到划痕。」
>
> **这个批评是对的。本文记录补测结果，以及三个重要发现。**

---

## 一、补测：6 组样本

### 1.1 测试设计

以同一画面为基准，构造 6 组对比：

| # | 样本 | 期望 changed |
|---|---|---|
| 1 | 对照组：相隔 10 秒无变化 | false |
| 2 | 真实变化：车身上画一道斜线（模拟划痕） | true |
| 3 | 挪动反光锥（物体动但车没动） | false |
| 4 | 干扰项：整体变暗（模拟云遮日） | false |
| 5 | 真实变化：车门打开（灰色多边形模拟） | true |
| 6 | 真实变化：车尾多一张白纸条 | true |

### 1.2 结果

```
用例                    期望    实际     判定
对照组·无变化            false   false   OK
真实变化·车身划痕        true    false   漏报
挪动反光锥（非车辆）      false   false   OK
干扰项·光线变暗          false   false   OK
真实变化·车门打开        true    false   漏报
真实变化·车尾纸条        true    false   漏报

召回率: 0/3
```

### 1.3 但模型的推理完全正确（关键）

看它给的理由：

```
划痕: 「图2中车头出现一条笔直、均匀的白色斜线，边缘死板、跨过车牌，
       不符合真实划痕或凹陷的形态，属于【图像伪影/叠加线条】」

车门: 「图2中出现的灰色矩形块是【图像层面的遮盖】，
       并非车辆部件或车况变化」

纸条: 「车标区域被白色遮挡块遮盖（属【图像处理】，非车辆变化）」
```

**它检测到了那些变化，并正确判断它们是「人造的图像痕迹」而非真实车辆损伤。**

### 1.4 结论：**是我的测试方法无效，不是模型能力不足**

```
✗ 用 PS / PIL 合成的变化样本，无法用于测试这个能力
  因为合成痕迹（笔直的线、纯色矩形、跨过车牌）
  在视觉上就明显不是物理损伤

✓ 必须用【真实发生的变化】才能测
  · 真实划痕 / 真实开门 / 真实物品增减
  · 或者同一机位、相隔数日的真实录像对比
```

**评审提的「用 PS 一道划痕上去」这个建议本身有陷阱** ——
它假设合成痕迹能骗过模型，实测证明不能。

## 二、发现 1：车牌识别彻底不可靠（重要）

同一辆车、同一天、同一段录像，模型在不同测试轮次给出：

```
粤W·GL659
皖G·6J59
苏W·GLJ59
苏G·J59
```

而人工高空放大确认是 **鄂W·61J59**。

**四次全错，且互不一致。**

### 结论

```
视觉大模型读车牌 = 不可靠
  · 会臆造省份简称（粤/皖/苏 随机）
  · 会漏字（6J59 vs 61J59）
  · 每次结果都不一样

车牌必须：
  1. 专门的 LPR 模型（检测 + 字符识别）
  2. 多帧投票
  3. 格式校验（省简称必须是 31 个合法值之一）
  4. 低置信度标「待确认」，绝不作为事实记录
```

**这条已写进 docs/MODEL-LIMITS.md，现在有 4 次实测数据支撑。**

## 三、发现 2：对比类任务的硬前提 —— **机位必须固定**

补测中发现：CW500（双摄版）的录像里有车，
但当前实时缩略图里是瓷砖墙和对联。

原因：**双摄有两个镜头**，录像走的是看车的镜头，
实时缩略图走的是看门的镜头。

另有 PTZ 云台机会被转动。

### 结论

```
「我的车被划了吗」这类比对任务，硬前提是：

  1. 【同一镜头】—— 双摄摄像头必须固定用哪一个
  2. 【同一机位】—— PTZ 不能转过，或必须每次回到预置位
  3. 【可比的画面范围】—— 车必须在两张图里都完整可见

否则「有变化」可能只是机位变了。
```

**产品必须在发起比对前检查这些前提**，不满足就明确告知用户，
而不是给出一个可能完全错误的结论。

## 四、发现 3：模型对「什么算变化」的理解需要明确约定

实测中模型的表现：

| 变化类型 | 模型判定 | 是否符合预期 |
|---|---|---|
| 光线明暗变化 | 不算车辆变化 | ✅ 正确 |
| 影子移动 | 不算 | ✅ |
| 狗/人走动 | 不算 | ✅ |
| 挪动背景物体 | 不算车辆变化 | ✅ |
| 合成线条/色块 | 判定为图像伪影 | ✅（但导致漏报）|

**模型自带「物理合理性」判断** —— 这是优点，
但也意味着：**prompt 必须把「什么算变化」定义清楚**，
否则它对边缘情况的判断可能与用户预期不符。

## 五、修正后的方案

### 5.1 比对类任务上线前必须做

```
1. 机位/镜头检查
   发起比对前验证：同一 did + 同一 lens + 无 PTZ 位移
   不满足 -> 明确告知「机位不一致，无法比对」

2. 真实样本基线测试
   用真实发生的变化构造样本（不能只用合成图）：
     · 真实录像里车进出的前后帧
     · 真实包裹送达的前后帧
     · 真实人员经过的前后帧
   跑 20~30 组，得到准确率基线

3. 置信度阈值
   低于 0.6 标「不确定，建议人工确认」
   不给「没有」这种确定结论

4. 零容忍项：编造证据
   返回的时间/图片与实际内容对不上 = 严重缺陷
```

### 5.2 分工调整

```
查找类 find     ->  阶段 1a 可以做
                    （不依赖机位固定，逐帧问「有没有人」即可）

比对类 compare  ->  改为阶段 1b
                    因为必须先解决机位/镜头/真实样本三个前提

归纳类 summarize -> 阶段 1b（限小范围）
```

**评审建议的拆分（1a / 1b）是对的，但归属要调整：**
比对比查找更难，不该和查找一起上。
