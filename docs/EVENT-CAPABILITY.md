# 小米摄像头「事件能力」调研报告

> 2026-09-16 · 针对 CW500（isa.camera.hlmax）和 CW300（mxiang.camera.moc001）
> 全部结论都有**实测证据**，非推测。

---

## 零、一句话结论

```
设备**有能力**产生丰富事件（规格里有 19 个事件定义）
但小米云 API **不向我们开放**这些事件的读取权限
唯一可行的路：继续用我们自己的帧差侦测
```

---

## 一、设备规格里有 19 个事件（这是真实存在的）

从官方 miot-spec 下载（`docs/specs/spec-cw500.json`）：

### CW500（siid=6 other-functions 服务）

| eiid | 事件 | 说明 |
|---|---|---|
| 1 | event-motion-dome | 移动侦测（球机） |
| 2 | event-motion-box | 移动侦测（枪机） |
| 3 | **people-motion-dome** | **有人移动** |
| 4 | people-motion-box | 有人移动 |
| 5 | **detected-car-dome** | **检测到车** |
| 6 | detected-car-box | 检测到车 |
| 7 | people-near-car-dome | 人靠近车 |
| 9/11 | ir-on/off | 红外开/关 |
| 13 | sound-light-alarm | 声光报警 |
| 14/16 | people-in/out-fence | 围栏进出 |
| 18 | timelapse-finish | 延时摄影完成 |

### CW300（service siid=8 ai-detection / siid=18 sound-and-light）

| eiid | 事件 | 说明 |
|---|---|---|
| 4 | **object-motion** | 物体移动 |
| 5 | **someone-appeared** | **有人出现** |
| 1/2 | ir-turned-on/off | 红外开/关 |
| 1 | sound-and-light-warning | 声光报警 |

**这些事件在米家 App 里会变成推送通知。**
（「有人经过」「检测到车辆」这类）

## 二、但云端 API 拿不到（实测）

### 2.1 MIoT 属性接口 —— 全部拒绝

```
POST api.io.mi.com/miotspec/prop/get
  {"params":[{"did":"1149106927","siid":1,"piid":2}]}   // 读型号
  -> {"code":-704010000}   属性不存在

  同样测试了 siid=13(ai-detection) siid=5(motion) siid=6(声光)
  批量 3 个属性 -> 全部 -704010000
```

**连最基本的「读型号」都失败** → 不是权限问题，是**设备不支持云端 MIoT 属性**。

### 2.2 MIoT 事件接口 —— 接口不存在

```
POST /miotspec/event/subscribe  -> HTTP 404
POST /miotspec/action           -> code=-8 data type not valid
```

### 2.3 设备数据接口 —— 存在但被权限拦

```
POST /user/get_user_device_data
  {"did":"1149106927","time_start":...,"time_end":...}
  -> code=-8 msg=no permit      ← 参数对了，但权限不足

对照：米家恒温电水壶 -> ✅ []   （空数组 = 有权限、没数据）
      摄像头           -> ✅ []  / no permit（交替出现）
```

注意 `no permit` 和 `[]` **交替出现** —— 说明小米对这个接口有节流，
但**核心结论不变**：摄像头的数据维度拿不到内容。

### 2.4 其它域名

```
app.io.mi.com   -> DNS 无法解析
cn.api.io.mi.com -> DNS 无法解析
mqtt.io.mi.com  -> DNS 无法解析
```
（米家 App 用的是内网推送服务，公网不可达）

### 2.5 摄像头局域网端口

```
192.168.1.7  (CW500): 54321 关闭   80 关闭
192.168.1.2  (CW300): 54321 关闭   80 关闭
```
（54321 是小米设备常用的 miIO 本地端口，这两台**没开**）

除了我们已经在用的 P2P（cs2）通道，**没有别的本地入口**。

## 三、为什么米家 App 能收到推送

```
米家 App 走的是**小米内部推送通道**：
  设备 --P2P/MQTT--> 小米云 --专有 push--> 米家 App

这条通道需要：
  1. 米家 App 的私有鉴权（不是 xiaomiio 的 serviceToken）
  2. 长连接（MQTT over 私有协议）
  3. 小米未公开的 push 订阅协议
```

**逆向成本极高、稳定性无保障**，且违反小米服务条款。**不建议做。**

## 四、我们现有的方案（帧差侦测）

### 原理

```
复用缩略图缓存：每台在线摄像头每 8 秒有一张 640px 的图
  -> 灰度降采样到 160x90
  -> 与上一帧做平均绝对差
  -> 超阈值（6.0）判为「移动」
```

### 实测性能

```
CPU 开销：几乎为零（图已在内存）
响应延迟：8~16 秒（采样间隔 + 抓帧耗时）
准确度：能检测「有变化」，不能判「是不是人」
误报：树影、雨雪、夜间红外切换
```

### 对比云端事件

| 维度 | 云端事件（不可用） | 我们的帧差 |
|---|---|---|
| 类型识别 | 人/车/包裹/围栏 | 只能「移动」 |
| 延迟 | 秒级 | 8-16 秒 |
| 准确度 | 高（设备端 AI） | 中 |
| 可用性 | ❌ 拿不到 | ✅ 可用 |

## 五、还能改进什么（不需要云端）

### 5.1 用本地 AI 补上「人形识别」

```
思路：把帧差触发的截图送本地模型分类
可选方案：
  · YOLOv8n（~6MB，CPU 上 ~50ms/帧）
  · MobileNet-SSD（更小更快，精度略低）
  · ONNX Runtime（Go 有绑定）

成本：每台摄像头每次触发跑一次推理，CPU 峰值约 30-50%
收益：把「移动」升级成「有人 / 有车」，对齐云端事件的能力
```

> 这是**唯一能在不依赖小米云的前提下**达到云端事件效果的方案。

### 5.2 侦测区域（减少误报）

```
现状：全画面比较，树影/马路都会触发
改进：允许用户框选「侦测区域」，只比较框内像素
      规格里 siid=13 piid=1 detection-area 就是干这个的
      （云端读不到，但我们可以在本地实现）
```

### 5.3 灵敏度分级

```
现状：固定阈值 6.0
改进：低/中/高三档，映射到不同阈值
      夜间自动放宽（红外噪声大）
```

### 5.4 双向验证（降误报）

```
现状：单帧差超阈值就记事件
改进：要求**连续 2 帧**都超阈值才算，减少瞬时噪声误报
```

## 六、结论与建议

### 已确认的事实

| 项 | 结论 | 证据 |
|---|---|---|
| 设备有能力产生事件 | ✅ | 规格里 19 个 eiid |
| 云端 MIoT 属性 | ❌ 不可用 | -704010000 |
| 云端 MIoT 事件订阅 | ❌ 接口不存在 | HTTP 404 |
| 设备数据接口 | ❌ 无权限 | no permit |
| 本地 miIO 端口 | ❌ 未开放 | 54321 关闭 |
| 帧差侦测 | ✅ 可用 | 已上线，累积 15 条事件 |

### 建议路线

```
短期（已做）：帧差侦测 + 事件中心，可用

中期（推荐）：接入本地 AI 模型
  · YOLOv8n 做人形/车辆识别
  · 把事件类型从「移动」升级到「有人/有车」
  · 完全本地，不依赖小米云

长期（可选）：
  · 侦测区域框选
  · 灵敏度分级 + 夜间自适应
  · 连续帧确认（降误报）

不做：逆向米家推送通道
  · 成本极高、稳定性差、违反服务条款
```
